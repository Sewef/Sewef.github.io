MacroHero Owlbear Extension

MacroHero Owlbear Extension Documentation

Welcome to the official user guide for MacroHero — the all-in-one macro and automation extension for Owlbear Rodeo. This documentation explains how to use MacroHero's features, visual editor, items, commands, and integrations to supercharge your virtual tabletop experience.

🔧 Pure JavaScript Scripting

MacroHero uses pure JavaScript for all expressions and commands. Variables are referenced directly by name (no special syntax), and you have full access to JavaScript operators, functions, and control structures. All integration functions are async and automatically awaited — use await when calling them in commands.

Getting Started

  1. Install MacroHero: Add the extension manifest URL https://macrohero.onrender.com/manifest.json using Owlbear Rodeo's "Install from manifest" option.
  2. Enable MacroHero in your Owlbear Rodeo session.
  3. Open MacroHero from the sidebar to access the main interface.

Visual Editor

  1. Click the Configuration (⚙️) button in the header to open the visual editor modal.
  2. The visual editor is a GUI wrapper around the underlying JSON configuration — every change you make updates the JSON and vice‑versa. There are no separate editor "tabs" or modes: the visual editor is the single interface for changing your configuration.
  3. Use the editor to add pages, define variables, and place items (buttons, values, inputs, counters, stacks, rows, dividers, etc.).
    • Add Page: give it a label and open it to add variables and layout items.
    • Add Variable: set a key and an expression. Optionally set numeric min/max.
    • Add Item: pick a type (value, input, checkbox, counter, button, text, title). Configure its label, link it to a var (when applicable), and add commands arrays to buttons.
  4. Commands: buttons accept an array of command strings — they execute sequentially when clicked. Commands are written in pure JavaScript and run in an async context. Use await when calling integration functions (e.g., await OwlTrackers.addValue(token, 'HP', 10)), reference variables by name, use operators, conditionals, and any standard JavaScript syntax.
  5. Counter items respect the variable's min/max and accept an optional step setting (default 1).
  6. Save / Cancel: Use the modal controls to save changes (persisted per-room) or cancel to discard edits. Changes are written to room metadata/local storage as appropriate.
  7. Validation & Debug: the editor validates syntax where possible; use temporary value items to surface intermediate variables and test expressions before using them in commands.

Visual Editor Modal Walkthrough

  • Global Title: Sets the extension title shown in the header.
  • Width / Height: Canvas size for the extension window.
  • Global Variables: Add variables that are available to all pages by referencing them directly by name in expressions.
  • Pages: Add or open pages to edit their variables and layout. Use + Add Page to create new pages.
  • Save / Cancel: Use the buttons in the modal corner to persist or discard changes.

Advanced Modal Features

Token Visualization Tool

The configuration modal includes a Token Viewer tab that displays all tokens and items currently in your Owlbear Rodeo scene. This tool helps you:

  • Find Token IDs: Quickly copy token IDs for use in your macros and expressions.
  • Browse Scene Items: View all items organized by layer (CHARACTER, PROP, MOUNT, ATTACHMENT, etc.).
  • Search & Filter: Search by name or filter by type to find specific tokens.
  • View Metadata: Expand items to see their full metadata, position, scale, and other properties.
  • Copy IDs: One-click copy of token IDs to clipboard for easy use in variable expressions like "token": { "expression": "'copied-token-id'" }

Usage: Open the config modal (⚙️) and click the Token Viewer tab. Use the search box to find tokens by name, or expand layers to browse all items. Click "Copy ID" next to any token to use it in your configuration.

Debug Mode

MacroHero includes a comprehensive Debug Mode system that lets you enable detailed console logging for specific modules. This is invaluable for troubleshooting expressions, commands, and integration calls.

  • Module-level control: Enable debug logging independently for each module (executor, expressionEvaluator, integrations, etc.).
  • Organized by categories:
    • Core Modules: executor, expressionEvaluator, ui, storage, parser, config, configModal
    • Command Modules: sceneHelpers, tokenHelpers, metadata modules
    • Integration Modules: GoogleSheets, OwlTrackers, Weather, JustDices, etc.
  • Category toggles: Enable/disable all modules in a category with one click.
  • Persistent settings: Debug modes are saved to localStorage and persist across sessions.
  • Real-time logging: When enabled, modules output detailed logs to the browser console showing variable resolution, command execution, API calls, and more.

Usage: Open the config modal (⚙️), click the Debug Mode tab, and check the boxes for modules you want to debug. Open your browser's developer console (F12) to see the logs. Useful for diagnosing why expressions return unexpected values or why commands fail.

Configuration Guide & Syntax

MacroHero is configured using a JSON structure that defines global variables, pages, UI layout, and commands. You can edit this configuration via the visual editor (⚙️) or by importing/exporting JSON. Below is a step-by-step guide with copy-pasteable examples for every feature.

The global Section

The global section sets up your extension's title, window size, and variables available everywhere. Here’s a real-world example:

{
    "global": {
      "title": "Macro Hero",
      "width": 800,
      "height": 600,
      "variables": {
        "playerName": {
          "expression": "Local.value('playerName', 'Unknown')"
        },
        "sessionId": {
          "expression": "OBR.session.id()"
        }
      }
    }
  }
  • title: The window title (shown at the top).
  • width / height: The extension window size in pixels.
  • variables: Global variables, available on all pages. Each variable uses an expression (see below for syntax).

Defining Variables & Expressions

Variables are defined in the variables section of either global or a page. Each variable uses an expression string written in pure JavaScript. You can reference other variables directly by name, use standard JavaScript math operators, call integration functions, and use any JavaScript syntax (ternary operators, string concatenation, etc.).

{
    "variables": {
      "hp": { "expression": "OwlTrackers.getValue(token, 'HP')" },
      "isBandaged": { "expression": "ConditionMarkers.hasCondition(token, 'Bandaged')" },
      "bonus": { "expression": "5" },
      "total": { "expression": "hp + bonus" }
    }
  }
  • Reference variables directly by name (no curly braces) in expressions and commands.
  • Supported functions: GoogleSheets.getValue, Local.value, OwlTrackers.getValue, ConditionMarkers.hasCondition, etc.
  • Use math and logic: (hp > 10 ? 'Healthy' : 'Wounded')
  • Optional numeric bounds: Variables may include optional min and max numeric properties. These are used by counter UI items (see below) to constrain the input range.

Creating & Organizing UI Items

Each page's layout array defines the UI. You can use these item types:

  • title: Section heading.
    { "type": "title", "text": "Section Name" }
  • text: Paragraph or note.
    { "type": "text", "content": "Some info" }
  • divider: Horizontal line.
    { "type": "divider" }
  • value: Display a variable.
    { "type": "value", "var": "hp", "label": "HP" }
  • input: Text input.
    { "type": "input", "var": "inputName", "label": "Name" }
  • checkbox: Checkbox input.
    { "type": "checkbox", "var": "isActive", "label": "Active?" }
  • counter: Number input. Use step (optional, default 1) to set increment/decrement amount. If the referenced variable defines min and/or max, the counter will respect those bounds.
    { "type": "counter", "var": "counterVar", "label": "Counter", "step": 1 }
  • button: Clickable button.
    { "type": "button", "label": "Heal 10", "commands": ["OwlTrackers.addValue(token, 'HP', 10)"] }
  • row: Horizontal group.
    { "type": "row", "children": [ ... ] }
  • stack: Vertical group.
    { "type": "stack", "children": [ ... ] }

Writing Commands & Using Integrations

Buttons and some other items use commands (an array of strings) to perform actions. Each command is a JavaScript expression that executes in an async context when the button is clicked. Commands can:

  • Call integrations (use await): await OwlTrackers.addValue(token, 'HP', 10)
  • Use variables: await JustDices.roll('Player: ' + playerName)
  • Use JavaScript logic: isBandaged ? ... : ...
  • Modify variables: revives = revives - 1
  • Use any JavaScript syntax: arithmetic, string manipulation, function calls, etc.
{
    "type": "button",
    "label": "Heal if Bandaged",
    "commands": [
      "await (isBandaged ? OwlTrackers.addValue(token, 'HP', 10) : OwlTrackers.addValue(token, 'HP', -5))"
    ]
  }

Supported integrations include: GoogleSheets, Local, OwlTrackers, StatBubbles, ConditionMarkers, ColoredRings, PrettySordid, JustDices. See the default config for more function names and usage.

JSON Structure for Pages, Layouts, and Commands

{
    "global": { ... },
    "pages": [
      {
        "label": "Page Name",
        "variables": { ... },
        "layout": [ ... ]
      }
    ]
  }
  • global: Global settings and variables.
  • pages: Array of page objects, each with its own variables and layout.
  • layout: Array of UI items (see above).

Saving & Persistence

MacroHero stores different kinds of data in different places to balance persistence, size limits, and privacy:

  • Full configuration: The complete JSON (pages, variables, layout) is saved to your browser localStorage using a room-scoped key (internal key: com.sewef.macrohero/fullConfig/<roomId>). This is written when you save in the configuration modal and on automatic saves.
  • Local (editable) variables: Only values for editable variables (inputs, counters, checkboxes) are saved to the Owlbear Rodeo Room metadata under the key com.sewef.macrohero/playerConfigs, namespaced by player ID. This persists across reloads and is shared within the room (but namespaced to avoid collisions).
  • Google Sheets credentials: API key and Sheet ID are stored in browser localStorage under macrohero.gsheet.apiKey and macrohero.gsheet.sheetId. The config modal enforces that credentials are provided when the configuration references Google Sheets.
  • Local integration storage: The `Local` integration (`Local.set` / `Local.value`) stores data in-memory for the current session. It does not persist across page reloads by itself — to persist values, bind them to editable UI variables (inputs/counters/checkboxes), which are saved to room metadata.
  • Notes & warnings: Room metadata is shared among extensions and players; MacroHero namespaces saved values by player ID to avoid accidental overwrites and saves only a compact set of editable values to keep metadata small.

Important — Backup Your Configuration

The full configuration JSON is stored in your browser localStorage. It can be lost if you clear site data, switch browsers/devices, or if localStorage is unavailable. Please export or copy your configuration from the JSON editor and save it to external storage (cloud drive, local backup, etc.).

Integrations

MacroHero provides integrations with popular Owlbear Rodeo extensions and external services. All integration functions are async and should be used with await in commands.

  • GoogleSheets: Read values from a Google Sheet (requires API key and Sheet ID).
  • Local: Store and retrieve data locally in browser storage.
  • OwlTrackers: Read and modify HP trackers on tokens.
  • StatBubbles: Manage token stats (HP, AC, etc.).
  • ConditionMarkers: Add, remove, and check conditions on tokens.
  • ColoredRings: Manage colored rings around tokens.
  • JustDices: Roll dice and display results.
  • PrettySordid: Manage initiative and turn order.
  • Weather: Control weather effects on maps.

See the detailed API reference below for all available functions.

Integrations API Reference

This section documents all public functions exposed by MacroHero's built-in integrations. Use these functions in variable expressions and in commands. Examples show how to call them from configuration JSON (expressions) or commands.

Local

  • value(key, default) → returns any
    Read a local value. Example: Local.value('playerName', 'Unknown')
  • set(key, value) → returns value
    Store a value locally. Example command: Local.set('playerName', 'Xalithra')
  • clear() → void
    Clear all local keys stored by MacroHero.
  • keys() → Array
    Return stored keys array.

GoogleSheets

  • getValue(sheetName, range) → Promise<any>
    Convenience helper exposed in expressions: GoogleSheets.getValue('Sheet1', 'A1') (returns a single cell when possible).
  • getRange(sheetName, range) → Promise<Array>
    Convenience helper exposed in expressions: GoogleSheets.getRange('Sheet1', 'A1:B4'). Returns a 2D array (or a flattened 1D array for single-column ranges).
  • Note: Due to API restrictions, GoogleSheets integration is read-only.

JustDices

  • roll(expression, options|hidden) → Promise<number>
    Roll dice using JustDices and return the total. Example: JustDices.roll('1d20+5')
  • getRollObject(expression, options|hidden) → Promise<Object>
    Return full roll details (rolls, total, raw data).
  • rollSilent(expression, hidden) → Promise<number>
  • getRollObjectSilent(expression, hidden) → Promise<Object>
  • options: boolean (hidden).

OwlTrackers

  • getValue(tokenId, trackerName) → Promise<number|null>
    Read a tracker value from a token (e.g., HP).
  • getMax(tokenId, trackerName) → Promise<number|null>
  • setValue(tokenId, trackerName, value) → Promise<void>
  • addValue(tokenId, trackerName, delta) → Promise<void>
    Add (or subtract if negative) a value to the tracker.

StatBubbles

  • getValue(tokenId, statName) → Promise<number|null>
  • setValue(tokenId, statName, value) → Promise<boolean>
  • addValue(tokenId, statName, amount) → Promise<boolean>
  • getAllStats(tokenId) → Promise<Object|null>
  • getHealthPercentage(tokenId) → Promise<number|null>
  • heal(tokenId, amount) → Promise<boolean>
  • damage(tokenId, amount) → Promise<boolean>

ConditionMarkers

Important — Choose the right ConditionMarkers Extension

For full API support, you must use either ConditionMarkers-API (manifest), which is identical but exposes a dedicated API, or ConditionMarkers-Extended (manifest), which adds the API and enables numeric value support for conditions.
The default ConditionMarkers extension does not provide API access or numeric value features. The two extensions above have been built to be fully compatible with MacroHero's ConditionMarkers integration.

  • getConditions(itemId) → Promise<Array>
    Return an array of condition objects applied to an item (token).
  • addCondition(itemId, conditionName, value?) → Promise<any>
    Add a condition; value is optional and may be a number/string/boolean.
  • removeCondition(itemId, conditionName) → Promise<any>
  • toggleCondition(itemId, conditionName) → Promise<void>
  • clearAllConditions(itemId) → Promise<void>
  • hasCondition(itemId, conditionName) → Promise<boolean>
  • getValue(tokenId, conditionName) → Promise<number|null>
    Read numeric value stored on the textual label of a condition marker (if present).

ColoredRings

  • getRings(tokenId) → Promise<Array<string>>
    Returns an array of color hex strings for rings attached to the token.
  • hasRing(tokenId, color?) → Promise<boolean>
  • addRing(tokenId, color) → Promise<boolean>
  • removeRing(tokenId, color) → Promise<boolean>

PrettySordid

  • hasInitiative(itemOrId) → boolean
    Sync-safe check (works if you have the item object; otherwise use the async helpers below).
  • getInitiativeCount(itemOrId) → Promise<number>
  • isActiveTurn(itemOrId) → Promise<boolean>
  • setInitiativeCount(itemOrId, count) → Promise<void>
    Accepts either an item object or token id string.

Embers

Embers provides a fluent API for creating and chaining spell visual effects (projectiles, area effects, cone effects, and gameplay actions) using the Embers extension for Owlbear Rodeo.

  • sequence() → EmbersSequence
    Create a new spell effect sequence. Supports method chaining for building complex effect chains.
    Example: await Embers.sequence().projectile('effectId', caster, target).cast()
EmbersSequence Fluent Methods
  • .projectile(effectId, casterId, targetIds, config?)
    Add a projectile effect from a caster to one or more targets.
    Params: effectId (string), casterId (token id), targetIds (token id or array), config (optional: size, spellName, etc.)
    Example: .projectile('generic.weapon_attacks.ranged.laser_shot.orange', caster, target, {spellName: 'Fireball'})
  • .aoe(effectId, tokenIds, config?)
    Add an area-of-effect (AOE/circle) effect at one or more token positions.
    Params: effectId (string), tokenIds (token id or array), config (optional: size, spellName, etc.)
    Example: .aoe('generic.impact.fire', targetToken, {size: 5, spellName: 'Explosion'})
  • .cone(effectId, casterId, targetId, config?)
    Add a cone effect from a caster directed at a target (rotation calculated automatically).
    Params: effectId (string), casterId (token id), targetId (token id), config (optional: size, spellName, etc.)
    Example: .cone('generic.weapon_attacks.melee.single.generic_slash', caster, target, {size: 6, spellName: 'Cone Attack'})
  • .action(actionId, args, config?)
    Add a gameplay action (move, create token, slide, etc.).
    Params: actionId (string), args (object), config (optional configuration)
    Example: .action('move', {target: targetId, distance: 10})
  • .delay(ms)
    Add a delay (in milliseconds) before the next effect executes. Delays stack and apply to the following effect.
    Example: .delay(300) delays the next effect by 300ms.
  • .then()
    Create a nested sequence where following effects execute only after all previous effects complete. Use for sequential effect chains.
    Example: .projectile(...).then().aoe(...) — projectile fires first, then AOE executes after.
  • .cast(options?) → Promise<void>
    Execute and broadcast the effect sequence to the Embers extension. Must be called to trigger the effects.
    Params: options (optional: spellName, destination for broadcast, etc.)
    Example: await Embers.sequence().projectile(...).cast()
  • .named(name)
    Set a spell name for the sequence (used by Embers for displays).
    Example: .named('Fireball')
  • .withOptions(options)
    Set additional options for the sequence (spellName, destination, interactions, spellData, etc.).
    Example: .withOptions({spellName: 'Lightning Bolt'})
Convenience Helpers
  • castProjectile(effectId, casterId, targetIds, config?) → Promise<void>
    Shortcut: create and cast a projectile effect in one call.
    Example: await Embers.castProjectile('effectId', caster, target, {spellName: 'My Spell'})
  • castAOE(effectId, tokenIds, config?) → Promise<void>
    Shortcut: create and cast an AOE effect in one call.
    Example: await Embers.castAOE('effectId', target, {size: 5})
  • castCone(effectId, casterId, targetId, config?) → Promise<void>
    Shortcut: create and cast a cone effect in one call.
    Example: await Embers.castCone('effectId', caster, target, {size: 6})
  • sendInstructions(instructions, options?) → Promise<void>
    Advanced: send raw instruction objects directly to the Embers extension (for expert users building effects manually).
Embers Examples

Single Projectile Effect

await Embers.sequence()
  .projectile('generic.weapon_attacks.ranged.laser_shot.orange', caster, target)
  .cast()

Projectile Followed by AOE (Sequential)

await Embers.sequence()
  .projectile('generic.weapon_attacks.ranged.laser_shot.orange', caster, target, {spellName: 'Fireball'})
  .then()
  .aoe('generic.impact.fire', target, {size: 5})
  .cast()

Multiple Projectiles (Simultaneous)

await Embers.sequence()
  .projectile('effectId', caster, target1)
  .projectile('effectId', caster, target2)
  .projectile('effectId', caster, target3)
  .cast()

Cone Effect with Delay

await Embers.sequence()
  .cone('generic.weapon_attacks.melee.single.generic_slash', caster, target, {size: 6, spellName: 'Cone Attack'})
  .named('Sweep')
  .cast()

Complex Chain with Delays

await Embers.sequence()
  .projectile('missile', caster, target, {spellName: 'Chain Lightning'})
  .delay(200)
  .then()
  .aoe('impact', target, {size: 4})
  .delay(300)
  .then()
  .cone('secondary', caster, target2, {size: 3})
  .cast()

Using Convenience Helpers

// Shortcut for simple projectiles
await Embers.castProjectile('effectId', caster, target, {spellName: 'Arrow'})

// Shortcut for AOE
await Embers.castAOE('effectId', target, {size: 5})

// Shortcut for cone
await Embers.castCone('effectId', caster, target, {size: 6})
How Delays Work

When you call .delay(ms), the delay is applied to the next effect, not the previous one. Delays stack — multiple consecutive .delay() calls add together.

// This delays the aoe by 300ms (projectile executes, then 300ms passes, then aoe fires)
Embers.sequence()
  .projectile('effect1', caster, target)
  .delay(300)
  .aoe('effect2', target)
  .cast()
How Sequential Execution Works (.then())

The .then() method creates a nested sequence where following effects execute after all previous effects complete. Without .then(), effects execute simultaneously. You can chain multiple .then() calls to create a complex sequence.

// Effects execute in order: projectile → (waits for completion) → aoe → (waits) → cone
await Embers.sequence()
  .projectile('missile', caster, target)
  .then()
  .aoe('impact', target, {size: 5})
  .then()
  .cone('secondary', caster, target2)
  .cast()
Notes on Embers
  • Async: Always use await when calling .cast() to ensure effects execute before the next command.
  • Fluent chaining: All methods except .cast() return the EmbersSequence instance for chaining.
  • Effect IDs: Use the correct Embers effect IDs for your extension version. Refer to the Embers documentation for available effects.
  • Positions fetched at cast time: Token positions are resolved when .cast() is called, not when methods are chained, allowing dynamic positioning.

Weather

Control weather effects on maps. Works with the official Weather extension. For advanced features (ENERGYSTORM, WATER, CURRENT weather types and tint color support), use the weather-extended fork.

  • setWeather(mapId, config) → Promise<void>
    Create or replace weather on a map. Config: {type, speed?, density?, direction?, tint?}
    Types: "SNOW", "RAIN", "SAND", "FIRE", "CLOUD", "BLOOM" (all extensions) + "ENERGYSTORM", "WATER", "CURRENT" (weather-extended only)
    Note: tint parameter requires weather-extended
    Example: Weather.setWeather(mapId, {type: 'SNOW', speed: 2, density: 3})
  • updateWeather(mapId, updates) → Promise<void>
    Update specific weather properties (e.g., tint, speed). Example: Weather.updateWeather(mapId, {tint: '#88aaff'})
  • removeWeather(mapId) → Promise<void>
    Remove weather from a map.
  • getWeather(mapId) → Promise<Object|null>
    Get current weather config or null.
  • hasWeather(mapId) → Promise<boolean>
    Check if map has weather.

Scene & Token Helpers

Advanced utility functions for scene manipulation. These are helper modules in /commands, not integrations.

  • sceneHelpers.getMapIdFromToken(tokenId) → Promise<string|null>
    Find which map a token is positioned on. Returns map ID or null.
  • sceneHelpers.createToken(params) → Promise<string>
    Create a single token. Params: {url, name?, position?, scale?, layer?, ...}
  • sceneHelpers.createTokens(tokensArray) → Promise<string[]>
    Create multiple tokens at once.
  • tokenHelpers: Additional token manipulation functions.

Note: These are exposed directly in the expression context for advanced users. See source code for complete API.

Metadata Modules (Advanced)

Low-level OBR SDK access for expert users. These modules provide direct metadata manipulation.

  • playerMetadata: Read/write player-specific metadata.
  • sceneMetadata: Read/write scene-level metadata.
  • tokenMetadata: Read/write token metadata.
  • tokenAttachments: Manage token attachments.

These expose raw OBR SDK operations. Use with caution. Refer to source code for function signatures.

Integrations Manager (Advanced)

Low-level manager functions for integration initialization. Most users won't need these.

  • initializeIntegrations(config) → void
    Initialize integrations with a config object. Called automatically by MacroHero.
  • getIntegrationsContext() → Object
    Returns the full integrations context (used internally).

Stack Item & Multi-Command Button Example

Use stack to group items vertically. Buttons accept multiple commands; they run in order. Here's a minimal example:

{
  "label": "Stack + MultiCmd",
  "variables": {
    "token": { "expression": "'your-token-id-here'" },
    "revives": { "expression": "2", "min": 0, "max": 5 }
  },
  "layout": [
    { "type": "title", "text": "Stack & Multi-Command" },
    { "type": "stack", "children": [
      { "type": "value", "var": "revives", "label": "Revives Left" },
      { "type": "input", "var": "note", "label": "Note" },
      { "type": "button", "label": "Use Revive & Roll",
        "commands": [
          "revives = revives - 1",
          "await OwlTrackers.addValue(token, 'HP', 10)",
          "await JustDices.roll('1d6')"
        ]
      }
    ]}
  ]
}

When the button is clicked it decrements revives, heals the token's HP by 10, then rolls a d6 and returns the result.

Advanced Usage

Advanced usage focuses on combining variables, expressions and integrations to build responsive and robust UI pages.

  • Lazy variable resolution: Commands only resolve variables they need for execution — structure expressions to minimize unnecessary work.
  • Use expressions for computed state: Keep UI items declarative; compute display values (e.g., derived stats) in variables not in button commands.
  • Respect min/max: Add min/max to numeric variables when you display them with counter items.
  • Async-safe commands: The executor auto-awaits async integration calls (e.g., OwlTrackers, GoogleSheets) — write commands naturally, but test any complex sequencing.
  • Permissions and safety: Treat third-party integration credentials (Google API keys) as secrets and store them only via the config modal.

Expressions & Debugging

  • Test expressions directly in the visual editor; use simple sub-expressions to isolate errors.
  • Prefer explicit numeric casts (e.g., Number(), floor()) when mixing strings and numbers.
  • If an expression returns unexpected values, check _resolved values in your exported config to inspect resolved results.
  • Use temporary value items to surface intermediate variables for debugging.

Async & Commands

  • All commands run in an async context. Use await when calling integration functions to ensure they complete before the next command executes.
  • Buttons can contain multiple commands — they run in order; each command is awaited automatically by the executor.
  • When using integrations inside expressions, expect network latency; keep UI responsive and avoid blocking long-running calls in critical UI paths.
  • Use setValue() and addValue() inside commands to modify page variables safely — those changes will trigger dependent variable recalculation.

Tips & Best Practices

  • Modular pages: Split unrelated macros across pages to improve discoverability and reduce per-page variable complexity.
  • Name variables clearly: Use descriptive variable names and keep expressions short and composed from smaller helper variables.
  • Reuse integrations: Use the Integrations Manager helpers (e.g., GoogleSheets.getValue) instead of calling low-level APIs yourself.
  • Backup: Export your configuration regularly via Import/Export to keep a backup of working setups.

Troubleshooting & Common Issues

Quick fixes

  • UI not updating: Click Reload Variables. If still stale, reload the extension or the page and check the browser console for errors.
  • Expression errors: Simplify the expression into smaller parts and validate each; ensure referenced variables exist.
  • Commands failing: Inspect the console for stack traces; add a temporary button that runs a simple diagnostic command (e.g., JustDices.roll('1d6')).

Google Sheets

  • Credentials: Ensure API key and Sheet ID are set in the config modal; check browser console for GSheets API errors.
  • Ranges: Use the correct sheet name and A1-style ranges; when reading single cells, prefer GoogleSheets.getValue('Sheet', 'A1').
  • Parsing numbers: Localized numeric strings are parsed automatically by the library, but if values are text in sheets ensure formatting is consistent.

Common mistakes

  • Not using the correct variable names in expressions — variables are referenced directly by name without curly braces.
  • Referencing missing variables — these evaluate to undefined or cause errors; ensure all referenced variables are defined.
  • Forgetting to pass token IDs to integration calls — many functions require a valid token id; use a page-level token variable.
